## Part 1 — Bugs found in the code read-through

### 1A. Clearly broken

**1. ✔ Solo-game AI ignores its own wins** — [src/lib/games/ai.js](src/lib/games/ai.js)
- Cause: the negamax functions score positions from the AI's fixed point of view (`w === me` → positive) but the caller negates the result as if the score were from the side to move. Result: winning moves score worst. Test: tic-tac-toe with a win at cell 2 picks the block at 5; Connect Four skips an open four-in-a-row.
- Fix: make every search function return the score **from the side to move**: terminal win for `toMove` → `+(BIG − depth)`, loss → `−(BIG − depth)`; heuristics (`c4Heuristic`, `checkersMaterial`, `chessMaterial`) evaluated for `toMove`; "no legal moves" → loss for `toMove`. The root keeps `score = -negamax(child, opp)`. Add `src/lib/__tests__/ai.test.js`: takes an immediate win, blocks an immediate loss (TTT + C4), takes a free capture (checkers), mates in one (chess).

**2. ✔ Deleting the first event of a repeating series deletes the whole series**
- Cause: `events.recurrence_parent_id … on delete cascade` (migration 042). The UI says "delete this event".
- Fix (migration 076): drop the FK and re-add it `on delete set null`. In [EventEditModal.jsx](src/components/EventEditModal.jsx) add the same "This event / This and following" choice to Delete that Save already has. "This and following" deletes `id = this OR (recurrence_parent_id = parent AND starts_at >= this.starts_at)`. When the parent itself is deleted with "this only", promote the next occurrence: `update events set recurrence_parent_id = <next id> where recurrence_parent_id = <old parent>` (do this in a `delete_event(p_event_id, p_scope)` RPC so it's atomic and creator-checked).

**3. ✔ DM header name does nothing; Connections ranking is meaningless**
- Cause: `get_my_chat_summaries` returns no peer user id, so `chat.personId` is undefined for every DM loaded from the server. [ThreadView.jsx:512](src/components/chat/ThreadView.jsx:512), [Chat.jsx:57](src/pages/Chat.jsx:57) and [Circles.jsx:56](src/pages/Circles.jsx:56) all depend on it. Circles' score also reads `chat.messages`, which never exists.
- Fix (migration 076): `drop function` + recreate `get_my_chat_summaries()` with an extra column `peer_id uuid` (the other member for `type = 'dm'`, else null). Map it in `mapChatSummaryRow` as `personId`. In `getInteractionScore`, replace the `messages`-based terms with `lastMessageAt` recency of the DM and `unread`, and drop the circle-chat "theyPosted" term (or feed it from a new `peer_last_message_at`). Keep the "DM" chip, which now works.

**4. ✔ Profile "Upcoming Meetups" shows the 3 oldest past events** — [Profile.jsx:106](src/pages/Profile.jsx:106)

  - EventDetailModal: render everything from `currentEvent`; after delete call `onClose()` and `refreshMeetups()`.

## Part 3 — New Home: the live wheel

Goal: Home stops being a menu of create actions and becomes a live "who's out, where, doing what" radar you can act on in one or two taps. The Gemini prototype is the functional reference; **visuals follow the current app** (tokens in `src/index.css`, components in `src/components/ui/ds.jsx`, Ember accent, light + dark, no Tailwind, no neon glow, 44 pt touch targets, reduced-motion support).

### 3.1 What the user sees

```
[third space.]                 (+)  (battery)  (bell)
[ Search people, circles, events            ]
Out now · 5 active                [All circles ▾]
 (You)  (Maya+2 stack)  (Liam)  (Elena+2)  →        ← avatar row
 ● Tap a slice to drop in, or a friend to pull up    ← context bar
           ┌──────────── wheel ────────────┐
           │        Study · 4 out          │
           │ Active        (center)  Food  │
           │  · 2           button   · 3   │
           │        Hang · 2 out           │
           └───────────────────────────────┘
 Up next (existing section, below the fold)
```

The wheel has three states (plus "you're checked in" as a variant of Radar):

| State | Wedges | Center button | Context bar |

### 3.2 Feature-by-feature

**F1 — Wheel becomes "something you want to do"; avatar row shows who's at each hangout; + opens a mini wheel anywhere**
- Home wheel = the Radar above (replaces the Circle/Event/LFG/Coffee wheel).
- Avatar row ("Out now"): each item is a **table**. A single person shows their avatar with the accent ring; a table with several people shows the **stacked group bubble** (F8) — up to 3 overlapping faces + "+N". Under it: first name(s) and "Spot · 45m".
- **Tap** the top-bar **+** → a **mini activity wheel** drops down right under it (popover, ~260 px, same four categories). It works on every tab: tap a category → the mini wheel flips to presets → Drop In, without leaving the current screen. When checked in, + shows your ring avatar (as today) and tapping shows your check-in with End / Extend.
- **Long-press** the **+** → a **mini create wheel** unfurls beneath it: **Event · Coffee · Circle** as three wedges (plus a center "Close"). Jake's bar: it must look very good, clean and professional, with a satisfying animation. Design:
  - Haptic `Medium` at the long-press threshold (350 ms); the + morphs into an ✕ (45° rotate).
  - The wheel grows out of the + button's position (transform-origin at the button): scale 0.6 → 1 and opacity 0 → 1 on a spring (stiffness 420, damping 30, no visible overshoot), wedges stagger in 40 ms apart with a short rotate-in (−12° → 0°). Backdrop dims to 30% with a light blur.
  - Each wedge: Lucide icon + label, `--surface-2` fill, accent outline + `Light` haptic on press, slight scale-down. Release-to-select also works (long-press, slide finger onto a wedge, lift) like iOS context menus.
  - Close: reverse of open in 180 ms. Reduced motion: fade only.
  - Selecting opens the existing create sheets, moved out of Feed into `src/components/create/CreateSheets.jsx` so they open from any tab.
  - Discoverability: the first-run tour gets a step "Hold + to create an event, coffee chat or circle".

**F2 — Zero-DM joining ("Pull Up")**
- In the Inspector, the center **Pull Up** button: one tap joins me to that table with an ETA of ~10 min (long-press shows 5 / 10 / 20 / 30 chips), notifies everyone at the table ("Jake is pulling up · ~10 min"), and my avatar joins their bubble with a small "on the way" clock badge until I arrive.
- "Arrived": automatically after the ETA, or tap "I'm here" (badge disappears). Undo within the ETA removes me and sends nothing further.
- No DM is created. Optional chat happens in the table note thread (F3).

**F3 — Ephemeral spot chat ("table notes")**
- Everyone at a table (host + everyone pulled up) gets a small thread: short notes ("grabbed the booth by the window"). Opens from the context bar 💬 or by tapping your own table. 140 chars, text only.
- Notes disappear when the check-in ends or expires (deleted server-side; hidden by RLS the moment it expires even before the purge runs).
- Push: a note notifies the table (respects the `free_now` pref, rate-limited to one push per person per table per 5 min).

**F4 — Live Radar**
- Four fixed categories, the same for everyone (Jake's decision): **Study**, **Food & Coffee**, **Hang**, **Active**. Each wedge shows the number of people out now in that category, counted from check-ins I'm allowed to see, within the current circle filter. Counts update live (realtime on check-ins/joins, plus a 60 s refresh).
- The wedge of the category I'm checked into is highlighted (accent outline, `--accent-soft` fill).

**F5 — Two-tap Drop In**
- Tap a wedge → the four wedges animate (rotate-flip, 220 ms; fade under reduced motion) into four **preset spots** for that category. Tap a spot → center becomes **Drop In** → tap → checked in. That's two taps (category, spot) plus the confirm; long-press a spot to drop in immediately.
- Presets per category, in order: (1) spots where people I can see are right now, (2) my saved favorites for that category, (3) spots I've checked into most, (4) nearest matching spots from `spots_near`. "Other spot…" opens a search (spots table + existing `searchVenues` fallback) and lets me save it as a favorite.
- Duration 1h / 2h / 3h (default 2h); visibility **All my circles (default — anyone who shares a circle with you, plus your connections)** / one circle / Friends only / Everyone.

**F6 — Spot Inspector**
- Tapping someone in "Out now" puts the wheel into the Inspector for their table: location (spot + address/area, tap → Maps), shared circle badge (the circle we share, or "Connection"), live countdown, open seats ("2 seats open", or "Open session" when seats aren't set). Center = Pull Up.

**F7 — Spot-anchored statuses**
- A status is now always "**at a place, doing a category, until a time**". Every check-in has a spot (or a custom place), a category and an expiry with a countdown everywhere it appears (avatar row, Inspector, your center button, push text "Maya is at Blue Donkey · 45m").
- The old free-form "I'm free" (activity text, no place) is migrated: existing active posts without a place show as "Somewhere · Hang".

**F8 — Stacked group bubbles**
- Everyone at the same table (host + pulled-up people), and different check-ins at the **same spot** from people who share a circle, merge into one bubble: overlapping avatars (max 3) + "+N", label "Maya, Alex +1". Signals "group hangout, low pressure". Tapping opens the Inspector for that table (if several tables at one spot, the wedges list them).

**F9 — Circle filtering**
- The "All circles ▾" pill opens a sheet of my circles. Picking one scopes the avatar row and the wedge counts to that circle's members (and check-ins posted to that circle). Remembered per device. The Circles tab gets a "Show on Home" action on each circle that sets this filter.

### 3.3 Data model (migration 076)

Evolve the existing `lfg_posts` instead of adding a parallel system — everything that already reads it (Discovery "Free now" cards, notifications, weekly goal, LFG targeting) keeps working.

```sql
-- check-ins = lfg_posts with a place, a category and seats
alter table public.lfg_posts
  add column category text check (category in ('study','food','hang','active')),
  add column spot_id uuid references public.spots(id) on delete set null,
  add column circle_id uuid references public.circles(id) on delete set null, -- scope
  add column seats int check (seats between 1 and 12),
  add column ended_at timestamptz;
alter table public.lfg_posts drop constraint lfg_posts_visibility_check;
alter table public.lfg_posts add constraint lfg_posts_visibility_check
  check (visibility in ('everyone','friends','circles','circle'));
-- one live check-in per person (close out old rows first so the index can build)
update public.lfg_posts set ended_at = expires_at where ended_at is null and expires_at <= now();
-- if a user still has several live rows, keep the newest: end the others
create unique index lfg_posts_one_live_per_user on public.lfg_posts (user_id)
  where ended_at is null;   -- plus expires_at handled by ending old ones in create_checkin

-- pull-ups ride on lfg_joins
alter table public.lfg_joins
  add column eta_at timestamptz,
  add column arrived_at timestamptz;

-- table notes (ephemeral)
create table public.checkin_notes (
  id uuid primary key default gen_random_uuid(),
  post_id uuid not null references public.lfg_posts(id) on delete cascade,
  user_id uuid not null references public.profiles(id) on delete cascade,
  text text not null check (char_length(text) between 1 and 140),
  created_at timestamptz not null default now()
);
-- RLS select: post is live (expires_at > now() and ended_at is null) and I'm the host or a joiner.
-- No direct insert: post_checkin_note() only.

-- favorites per category
create table public.wheel_favorites (
  user_id uuid references public.profiles(id) on delete cascade,
  category text not null,
  spot_id uuid references public.spots(id) on delete cascade,
  position int not null default 0,
  primary key (user_id, category, spot_id)
);

-- map OSM categories to wheel categories
create table public.wheel_category_kinds (category text, spot_category text, kind text);
-- study  ← kind in (library, cafe, coworking_space, university, college) + category coffee
-- food   ← category in (food, coffee, drinks)
-- hang   ← category in (outdoors: park/garden, sights, browse, drinks: bar/pub, arts)
-- active ← category active + kind in (fitness_centre, sports_centre, pitch, track, swimming_pool, climbing)
```

RPCs (all `security definer`, `auth.uid()` checked, never across a block):
- `get_wheel_state(p_circle_id uuid default null) → jsonb` — `{ me: <my live check-in + its table>, counts: {study,food,hang,active}, tables: [ { post, spot, category, host, members:[{id,name,avatar,status,eta_at}], shared_circle, seats_open, expires_at } ] }`. Visibility: everyone / friends (are_connected) / circles (shares any circle) / circle (member of `circle_id`). Grouping by spot for F8 is done here.
- `get_wheel_presets(p_category text, p_lat double, p_lng double) → jsonb` — the four presets in the F5 order.
- `create_checkin(p_category, p_spot_id, p_place jsonb, p_minutes int, p_visibility, p_circle_id, p_seats) → uuid` — ends my previous live check-in, inserts, notifies (existing targeting rules, `free_now` pref).
- `end_checkin()`, `extend_checkin(p_minutes)`.
- `pull_up(p_post_id, p_eta_minutes default 10) → jsonb` — wraps `join_lfg_post`, sets `eta_at`, enqueues `pull_up` notifications to the table. `cancel_pull_up(p_post_id)`. `mark_arrived(p_post_id)`.
- `post_checkin_note(p_post_id, p_text)` — membership + live check, rate-limit, `checkin_note` notification.
- Cron (`pg_cron`, every 10 min): `delete from checkin_notes where post expired or ended`; set `arrived_at = eta_at` when passed.
- `push_title_for`: add `pull_up` → "Pulling up", `checkin_note` → table name.
- Weekly goal: a pull-up that arrived counts as a meetup (it already counts joins).
- Grants: revoke from public/anon, grant to authenticated; internal helpers revoked from authenticated.

## Part 4 — Third Space inside iMessage

Goal: like GamePigeon — from inside a Messages conversation, send a Third Space card (an event, "I'm at Blue Donkey, come through", a circle invite, a quick poll of times) and let people **RSVP / pull up / join right in the bubble**. The main app stays the home base.

### 4.1 Why two layers
An iMessage app is a **native iOS app extension** (Swift, `MSMessagesAppViewController`); it can't run the Capacitor web app directly, and people without Third Space can't open it. So:

- **Layer A — Smart links (works for everyone, every platform, ships first).** Every shareable thing gets a public URL with a rich preview: `third-space-app.com/e/<id>` (event), `/s/<postId>` (live check-in), `/c/<code>` (circle invite, existing `/j/` codes), `/p/<id>` (time poll). In iMessage these render as large preview cards automatically (Open Graph image + title). Tapping opens the app via Universal Links (AASA — still pending from the last plan) or a web page with RSVP/join that sends you to sign up.
- **Layer B — iMessage extension (iOS, the GamePigeon-style experience).** A compact app drawer in Messages to create and send interactive bubbles; tapping a bubble expands it in Messages to RSVP/join without leaving the chat; the bubble updates for everyone ("5 going · Maya, Alex…").

### 4.2 Layer A build steps

> **Built 2026-11-11 (branch `smart-links`):** migration 080 (`public_event_card`, `public_checkin_card`, `events.share_enabled`; coffee chats and private-circle events never get public previews), `api/card.js` + `api/_cards.js` (Vercel Edge function that fills the app's own `index.html` with the card's title/description/image for `/e/:id`, `/s/:id`, `/j/:code`), `src/pages/ShareLanding.jsx` (signed-out card + remembered link), Home opens `?event=` / `?checkin=`, Share buttons on event details and your own Free-now post, AASA paths `/e/*` and `/s/*`. Images use the event cover or the app icon; generated preview images (`@vercel/og`) and `/p/` time polls move to Phase 8.
1. Public read RPCs (anon): `public_event_card(p_id)`, `public_checkin_card(p_id)`, `public_circle_card(p_code)` — only what a card shows (title, time, place name, host first name, counts, cover), only for shareable items (open circles / events with `share_enabled`, live check-ins with visibility everyone).
2. Vercel functions `api/og/[type]/[id].ts` that render a 1200×630 PNG (`@vercel/og`) with the app's look; and `api/card/[type]/[id]` returning HTML with OG/Twitter tags + a redirect for humans to the SPA route.
3. SPA routes `/e/:id`, `/s/:id`, `/p/:id` (public, outside AuthGuard, like `/j/:code`): preview + RSVP / Pull Up / Vote; signed-out → store a pending action (same pattern as `ts.pendingJoinCode`) → after sign-in perform it once.
4. "Share" buttons: EventDetailModal, check-in center button (long-press → Share), CircleDetail Invite, using `@capacitor/share` with the URL (iMessage turns it into a card).

### 4.3 Layer B build steps (iOS)
1. **Xcode (Jake):** add target *iMessage Extension* ("Third Space Messages") to `ios/App`; App Group `group.com.thirdspace.social` on both app and extension; Keychain Sharing group.
2. **Shared session:** small Capacitor plugin (`ios/App/App/SessionBridge.swift`) — whenever supabase-js stores/refreshes the session (our custom storage adapter in [supabase.js](src/lib/supabase.js)), also write it to the App Group keychain. The extension reads it; it refreshes tokens itself with supabase-swift and writes back.
3. **Extension UI (SwiftUI)** — v1 ships all four (Jake's decision). Compact (drawer) mode: four big tiles — *I'm out now* (pick category → spot → send), *Event* (pick one of my upcoming events or make a quick one: title/time/place), *Circle* (pick a circle → invite), *When works?* (3 time options poll). Expanded mode: the detail view for a tapped bubble with the action button.
4. **Bubbles:** `MSMessage` with `MSMessageTemplateLayout` (image = the same OG card PNG from Layer A, caption, subcaption "3 going") and `url` = the Layer A URL + `?v=` state. Use `MSSession` so updates replace the same bubble instead of stacking new ones. When someone RSVPs/pulls up/votes in the extension, call the RPC, then send the updated message in the session.
5. **Actions** call the same Supabase RPCs as the app (`rsvp`, `pull_up`, `redeem_invite_code`, a new `vote_time_poll`) via supabase-swift — no duplicate business logic.
6. **Not signed in / no app:** the bubble's URL opens the Layer A web page; the extension shows "Open Third Space to sign in".
7. **Limits to respect:** extensions get little memory (~120 MB) and no long-running work; keep it native and small; images from the OG endpoint, cached.
8. **App Store:** the extension ships inside the main app build (same review), needs its own icon set (Messages sizes) and screenshots.
9. Android has no equivalent: Layer A links + Android share sheet cover it.
